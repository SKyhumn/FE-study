# 5.Firestore DB

Firestore DB는 **Google Firebase**에서 제공하는 **클라우드 기반 NoSQL 데이터베이스**이다.

## 주요 특징

- **실시간 동기화**
    - 여러 기기나 클라이언트가 데이터를 동시에 수정해도 자동으로 업데이트 됨
- **클라우드 기반**
    - 서버 따로 안 만들어도 Firebase가 서버를 대신 관리함
- **크로스 플랫폼 지원**
    - Web, android, ios, node js 등에서 사용 가능
- **자동 확장성**
    - 트래픽이 늘어나도 서버를 직접 늘릴 필요 없음
- **보안 규칙**
    - 누가 어떤 데이터에 접근할 수 있는지 세밀하게 제어 가능

## Firestore DB구조

- **컬렉션(collection)**
    - 최상위 데이터 모음집(폴더 역할)
- **문서(document)**
    - 데이터 문서들
- **필드(field)**
    - 문서를 이루고 있는 데이터들

### 2.데이터 불러오기

먼저 규칙 탭으로 가서 코드를 수정한다.

![image.png](./img/스크린샷XVII)

**수정 전**

```tsx
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

**수정 후**

```tsx
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if true;
    }
  }
}
```

개발 테스트용 설정이므로 실제로 배포 시 절대 이렇게 두면 안된다.

## React에서 쓸 수 있는 Firestore 함수

### **참조 생성**

| **함수** | **설명** |
| --- | --- |
| `collection(db, "컬렉션 이름")` | 컬렉션 위치를 나타내는 참조 생성 |
| `doc(db, "컬렉션 이름", 문서 id)` | 컬렉션 안의 문서 하나를 나타내는 참조 생성 |

`collection()` 은 `collection(db, "컬렉션 이름", 문서 id, "하위 컬렉션 이름", 하위 문서 id ...)` 와 같이 **컬렉션⇒문서⇒하위 컬렉션⇒하위 문서** 순으로 파고들 수 있다.

### **데이터 추가/수정/삭제**

| **함수** | **설명** |
| --- | --- |
| `addDoc(collection(db, "컬렉션 이름"), {데이터 객체})` , `addDoc()` | 컬렉션에 문서를 추가한다. `collection()` 과 같이 쓰인다. |
| `setDoc(doc(db, "컬렉션 이름", 문서 id), {데이터 객체})` , `setDoc()` | 컬렉션에 있는 문서를 덮어 씌운다. `doc()` 과 같이 쓰인다. |
| `updateDoc(doc(db, "컬렉션 이름", 문서 id), {데이터 객체})` , `updateDoc()` | 컬렉션에 있는 문서를 일부 수정한다. `doc()` 과 같이 쓰인다. |
| `deleteDoc(doc(db, "컬렉션 이름", 문서 id))` , `deleteDoc()` | 컬렉션에 있는 문서를 삭제한다. `doc()` 과 같이 쓰인다. |

### `setDoc()` vs `updateDoc()`

둘 다 문서의 수정을 담당하나 차이가 있다.

| 상황 | setDoc | updateDoc |
| --- | --- | --- |
| 문서 없음 | **생성됨** | ❌ 에러 |
| 문서 있음 | 덮어쓰기 | 일부 수정 |

### `setDoc()` 도 부분 수정처럼 쓸 수 있다

```tsx
setDoc(
	doc(db, "컬렉션 이름", 문서 id),
	{ views:11 } // 객체 일부 수정
	{ merge:true }
);
```

`merge` 는 기존 데이터와 새 데이터를 병합 시킬 수 있다.

### 쿼리

| **함수** | **설명** |
| --- | --- |
| `quary(collection(db, "컬렉션 이름"), 조건문, 조건문...)` | 쿼리를 만드는 기본 함수. 단독으로 쓰이지 않고 조건 함수랑 같이 쓴다. |
| `where("필드", "연산자", "값")` | 조건 검색 기능, `==` , `!=` , `>=` , `>` , `<=` , `<` 의 연산자가 있다. |
| `orderBy("필드", "값")` | 정렬 기능, `asc` , `desc` 로 정렬이 가능하다. |
| `limit(값)` | 가지고 올 문서들의 개수를 제한한다. |

### 문서 가져오기

| **함수** | **설명** |
| --- | --- |
| `getDoc(doc(db, "컬렉션 이름", 문서 id))` | 특정 문서 하나를 가지고 온다. |
| `getDocs(collection(db, "컬렉션 이름"))` | 컬렉션 안의 문서들을 가져온다. |

### 문서를 가지고 왔다면?

`getDoc()` 이나 `getDocs()` 로 문서들을 가져올 시 스냅샷을 반환한다.

**`getDoc()`으로 가져왔다면?**

스냅샷 구조

```
DocumentSnapshot
 ├ id
 ├ data()
 ├ exists()
 └ ref
```

`data()` 에 문서 필드들이 들어있다.

**`getDocs()` 로 가져왔다면?**

스냅샷 구조

```
QuerySnapshot
 ├ docs (배열)
 │   ├ QueryDocumentSnapshot
 │   │    ├ id
 │   │    └ data()
 │   ├ QueryDocumentSnapshot
 │   │    ├ id
 │   │    └ data()
 │   └ QueryDocumentSnapshot
 │        ├ id
 │        └ data()
 ├ size
 └ empty
```

그래서 보통 이렇게 접근한다.

```tsx
snapshot.docs[0].id // "snapshot"은 변수 이름
snapshot.docs[0].data()
```

```tsx
const notes = snapshot.docs.map((doc) => ({
  id: doc.id,
  ...doc.data()
}));
```
